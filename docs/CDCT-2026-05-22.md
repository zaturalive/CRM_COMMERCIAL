### 3.2. Patterns

- **Prisma extended client** : middleware Express injecte `req.prisma` qui filtre automatiquement par `tenantId` du JWT
- **Anti-enumeration** : 404 plutot que 403 sur cross-tenant
- **Audit logs (V1)** : middleware logue toute mutation API dans `AuditLog`
- **Optimistic UI** : mutations affichent l'effet immediatement, revert si serveur fail
- **Transactions Prisma** : `$transaction` pour les operations multi-table (creation devis, reconcile stays, etc.)

### 4.2. Patterns

- **Server components by default** : sauf si besoin de hooks → `"use client"`
- **NextAuth session** : `useSession()` cote client, `getServerSession(authOptions)` cote server
- **i18n** : `useTranslations("Namespace")` cote client + serveur
- **Optimistic updates** : pattern `useState` local + revert si serveur fail (cf `DocumentsTab.handleUpload`)
- **Form validation** : composants controles + Zod schema partage frontend/backend (a creer en V1)
- **A11y** : aria-labels, focus management, keyboard nav (deja partiellement en place)

### 4.3. Securite frontend

- `NEXTAUTH_SECRET` strict 32 bytes
- Cookies session HttpOnly + SameSite=Lax + Secure en prod
- Pas de localStorage pour les tokens (sauf last-cabinet pre-fill, non sensible)
- CSP stricte (V1)
- Modal HDS sessionStorage `crm-commercial:hds-upload-consent` (P3)

## 11. Glossaire

- **Cabinet** : structure d'exercice = un tenant
- **Client** : beneficiaire d'une prestation esthetique (personne concernee RGPD)
- **Process** : parcours commercial d'un client pour une prestation
- **Prestation** : service esthetique du catalogue cabinet (anciennement "intervention")
- **Devis** : document commercial decrivant la prestation et son cout
- **Rendez-vous** : date client / praticien (ex "consultation")
- **Tenant** : espace isole d'un cabinet
- **HDS** : Hebergeur de Donnees de Sante (certification francaise)
- **non-HDS** : statut actuel du CRM Commercial (cf ADR-0003)
