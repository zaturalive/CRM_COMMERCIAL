# EP09-S03 — Notes par etape + log de qualifications

> **HDS-CHECK** (2026-05-18) — Verdict : `SUSPECT`
> Periode : NON-HDS (cf. ADR-0008 du repo source)
> Mots-cles BLOCKED detectes : aucun
> Mots-cles SUSPECT detectes : "patient" (preferer "client"), "note" texte libre (risque equivalent §7.5 du skill)
> Action : clarification user
> Justification : texte libre saisi par le commercial a chaque transition de sub-stage. Cas limite §7.5 du skill (qualificationReason) : risque que le commercial ecrive du contenu medical ("client souffre de X"). Mitigation a confirmer : guideline UI + clause contractuelle + audit periodique. Story implementable apres validation explicite du user.

**Epic** : Follow-up dedie • **Priorite** : Must have • **Estimation** : 2h30

## User story

En tant que **commercial**, je veux **ajouter une note et une qualification a chaque transition de sous-etape follow-up**, afin de **garder une trace du dialogue avec le patient** (a-t-il avance ? bloque encore sur l'argent ? a-t-il repondu ?).

## Acceptance Criteria

### Schema Prisma

1. Nouvelle table `FollowupStepLog` :
   - `id : UUID PK`
   - `processId : UUID FK Process` (cascade delete)
   - `fromSubStage : FollowupSubStage?` (null si entree initiale)
   - `toSubStage : FollowupSubStage` (NOT NULL)
   - `note : Text?` (commentaire commercial libre)
   - `progressLabel : Enum FollowupProgress?` ("AVANCE" | "STAGNE" | "RECULE" | "PAS_DE_REPONSE")
   - `userId : UUID FK User?` (qui a fait la transition, null si auto)
   - `occurredAt : DateTime DEFAULT now()`
   - `@@index([processId, occurredAt])`
2. Nouvel enum `FollowupProgress` : `AVANCE`, `STAGNE`, `RECULE`, `PAS_DE_REPONSE`

### API

3. La route `PATCH /api/processes/:id/follow-up-substage` accepte un body etendu :
   - `{ subStage, note?, progressLabel? }`
   - Cree un `FollowupStepLog` a chaque transition (auto)
4. Nouvelle route `GET /api/processes/:id/follow-up-logs` :
   - Retourne les `FollowupStepLog` du process (orderBy occurredAt desc)
   - Inclut `user.firstName + lastName` pour affichage
5. Nouvelle route `POST /api/processes/:id/follow-up-logs` :
   - Permet d'ajouter un log libre sans changer de sub-stage (note d'observation)
   - Body : `{ note, progressLabel? }`

### UI

6. Onglet "Suivi" dans ProcessPanel quand `stage = FOLLOWUP` (5e onglet, apres Documents)
7. Liste chronologique des `FollowupStepLog` :
   - Timeline verticale avec markers colores selon `progressLabel`
   - AVANCE = vert, STAGNE = amber, RECULE = rouge, PAS_DE_REPONSE = gris
   - Affichage : "[user] - [J0 → J3] - [Avance] - [date]" + note
8. Bouton "Ajouter une observation" en bas (dialog modal pour note + progressLabel)
9. Quand le commercial drag une card dans `FollowupView`, un mini-dialog s'ouvre :
   - Champ note (optionnel)
   - Champ progressLabel (radio buttons)
   - Bouton "Confirmer" → POST le PATCH avec note + progressLabel
   - Bouton "Sauter" → PATCH sans note (vers UX rapide)

## Tests

- Test integration : drag avec note → `FollowupStepLog` cree avec userId du request
- Test integration : `POST /follow-up-logs` cree un log sans changer le sub-stage
- Test unit : ordre chronologique respecte dans `GET /follow-up-logs`

## Notes techniques

- `FollowupStepLog.userId` populated via `req.user!.id` cote backend
- La timeline UI : pattern shadcn `Timeline` ou custom div avec border-left + dots
- Mini-dialog drag : reuse `<Dialog />` shadcn, declenche au moment du drop si `targetStage !== fromStage`
