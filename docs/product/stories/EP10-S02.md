# EP10-S02 — CRUD DocumentTemplate (page parametrage)

**Epic** : Document templates PDF • **Priorite** : Must have • **Estimation** : 3h

## User story

En tant que **administrateur**, je veux **creer, editer, et supprimer des templates de documents PDF** depuis la page Parametrage, afin que **le catalogue soit alimente avant utilisation par les commerciaux**.

## Acceptance Criteria

### API

1. Routes CRUD `DocumentTemplate` (ADMIN only, tenant-scope) :
   - `GET /api/document-templates?active=true|false`
   - `POST /api/document-templates` (Zod : name 1-200, kind, fileUrl XOR bodyHtml)
   - `PATCH /api/document-templates/:id`
   - `DELETE /api/document-templates/:id` (soft delete via `isActive=false`)
2. Route upload PDF dediee : `POST /api/document-templates/upload`
   - Multer middleware (10 MB max, mime `application/pdf`)
   - Stockage : `{tenantId}/templates/{uuid}.pdf` (reuse pattern existant cf documents)
   - Reponse : `{ fileUrl }` que le frontend utilise dans le POST `/document-templates`
3. Route preview PDF : `GET /api/document-templates/:id/preview` (auth + tenant scope)
   - Stream le PDF source (Content-Type application/pdf)
4. Route render PDF : `GET /api/document-templates/:id/render?processId=<id>` (cf EP10-S04 pour le rendu rempli)

### UI Parametrage

5. Nouvelle section "Templates de documents" dans `/config` (page parametrage), apres "Templates de messages" (EP09-S04) :
   - Onglets par `kind` : PDF uploaded / HTML render
   - Liste des templates : nom + preview thumb + active toggle + actions
6. Bouton "+ Nouveau template" → dialog modal :
   - Onglet 1 "Importer un PDF" :
     - File input PDF
     - Champ `name` + `description`
     - Apres upload → preview iframe + champ `variableSchema` (multi-select de `patient.firstName`, `intervention.name`, etc.)
   - Onglet 2 "Editer en HTML" :
     - Champ `name` + `description`
     - Textarea `bodyHtml` avec preview (iframe sandboxe)
     - Multi-select `variableSchema`
     - Bouton "Voir la liste des variables disponibles" → drawer cote
7. Toggle `isActive` inline sur la liste
8. Action "Supprimer" → confirmation dialog

### Variables disponibles

9. Liste fixe des variables exposees au MVP (definies dans `lib/templateVariables.ts`) :
   - `patient.firstName`, `patient.lastName`, `patient.phone`, `patient.email`, `patient.city`
   - `intervention.name`, `intervention.duration`
   - `cabinet.name`, `cabinet.slug`
   - `process.consultationDate`, `process.budget`
   - `devis.reference`, `devis.totalCached`
   - `user.firstName`, `user.lastName` (commercial qui genere)
   - `today` (date du jour formatee)

## Notes techniques

- Pour le PDF uploaded, le rendu rempli (EP10-S04) ne supporte PAS le remplissage automatique de champs PDF formes (PDFForm). Pour le MVP : annexer le PDF tel quel + une page de garde HTML→PDF avec les variables.
- Pour `kind=HTML_RENDERED`, on utilise Puppeteer (deja installe pour devis) pour generer le PDF a partir du HTML rendu
- Le service `lib/templateRenderer.ts` (cree en EP09-S04) est etendu pour accepter un `bodyHtml` et faire la substitution variables
