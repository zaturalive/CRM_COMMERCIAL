**Epic** : UI performance — optimistic updates • **Priorite** : Must have • **Estimation** : 1h30

## User story

En tant que **commercial**, je veux **que l'envoi/upload/suppression d'un document ne reload plus integralement la liste** (plus de loading spinner + perte de focus), afin de **garder une UX fluide quand je gere les documents d'un dossier**.

**Diagnostic du bug actuel** : `DocumentsTab.tsx` L55-65 → `reload()` fait `setLoading(true)` qui declenche le `if (loading)` L167 → conditional render qui remplace toute la liste par `<Loader2 size={14} className="animate-spin" /> Chargement...`. Visuel = la liste disparait pendant 1-2s.

## Acceptance Criteria

### Refactor `reload()`

1. Renommer `reload()` en `loadDocuments({ silent })` :
   - `silent=false` (default au mount) : `setLoading(true)` puis fetch puis `setLoading(false)` (comportement actuel)
   - `silent=true` : pas de `setLoading(true)`, fetch + `setDocs(res.data)` directement
2. Toutes les mutations (`handleStatusBump`, `handleUpload`, `handleDelete`, AddDocumentDialog `onSuccess`) appellent `loadDocuments({ silent: true })`

### Optimistic local

3. `handleStatusBump(doc)` :
   - Avant `apiFetch`, update `setDocs(prev => prev.map(d => d.id === doc.id ? {...d, status: nextDocumentStatus(d.status)} : d))`
   - Si echec → revert (re-set le status precedent)
4. `handleDelete()` :
   - Avant `apiFetch`, update `setDocs(prev => prev.filter(d => d.id !== deleting.id))`
   - Si echec → re-add (re-fetch ou push back)
5. `handleUpload(doc, file)` :
   - Avant fetch, update `setDocs(prev => prev.map(d => d.id === doc.id ? {...d, fileUrl: 'pending', status: 'RECU'} : d))`
   - Apres succes → `loadDocuments({ silent: true })` pour avoir le `fileUrl` reel
6. `AddDocumentDialog` `onSuccess` :
   - Lance `loadDocuments({ silent: true })` (ne sait pas la liste exacte des labels ajoutes — refetch est plus simple ici)

### UX detail

7. Le bouton "Status pill" (StatusPill) garde son anim `bumping` (scale 1.15) qui est purement local — non lie au reload
8. Toast success/error reste actif

## Tests

- Test E2E Playwright :
  - Bump status d'un doc → status change instantanement (timeout strict <100ms)
  - Aucune disparition de la liste pendant l'action
  - Upload d'un fichier → row reste visible, status passe a RECU directement
- Test unit : `optimisticUpdate` ne mute pas `prev` (pure function)
- Test : sur erreur backend, le revert restore le state precedent

## Notes techniques

- `useCallback` pour `loadDocuments` reste, ajout du parametre `silent` via closure
- Pas besoin de pattern react-query ici (la liste est petite, < 20 docs typiques)
- Le `<Loader2 />` initial reste sur le mount (UX premier chargement OK)
