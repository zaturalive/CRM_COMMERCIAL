## User story

En tant que **administrateur**, je veux **gerer un catalogue de templates de messages (mail, video, texte)** dans la page Parametrage, afin que **les commerciaux disposent d'un pool reutilisable pour relancer les patients**.

## Acceptance Criteria

### Schema Prisma

1. Nouvelle table `MessageTemplate` :
   - `id : UUID PK`
   - `tenantId : UUID FK Tenant`
   - `name : String` (ex "Relance J+3 mammoplastie")
   - `kind : Enum MessageKind` (MAIL | SMS_WHATSAPP | VIDEO)
   - `subject : String?` (uniquement pour MAIL)
   - `body : Text` (markdown autorise pour MAIL ; texte libre pour SMS/VIDEO)
   - `mediaUrl : String?` (URL externe YouTube / Vimeo / autre — pour VIDEO)
   - `previewImageUrl : String?` (vignette pour cartes UI)
   - `isActive : Boolean DEFAULT true`
   - `createdAt`, `updatedAt`
   - `@@unique([tenantId, name])`
   - `@@index([tenantId, isActive])`
2. Nouvel enum `MessageKind` : `MAIL`, `SMS_WHATSAPP`, `VIDEO`

### API

3. Routes CRUD `MessageTemplate` :
   - `GET /api/message-templates?kind=MAIL|SMS_WHATSAPP|VIDEO&active=true|false`
   - `POST /api/message-templates` (Zod : name 1-200, kind, body 1-10000, subject required if kind=MAIL, mediaUrl validate URL if kind=VIDEO)
   - `PATCH /api/message-templates/:id`
   - `DELETE /api/message-templates/:id` (soft delete via `isActive=false` plutot que delete dur — preserve les bindings cf S05)
4. Toutes les routes requièrent ADMIN
5. Tenant-scope automatique via `req.prisma!`

### UI Parametrage

6. Nouvelle section "Templates de messages" dans `/config` (page parametrage)
7. Liste filtrable par `kind` (3 onglets : Mail / SMS-WhatsApp / Video)
8. Bouton "+ Nouveau template" → dialog modal avec :
   - Champ `name`
   - Select `kind`
   - Champ `subject` (visible si kind=MAIL)
   - Textarea `body` avec preview markdown (uniquement MAIL)
   - Champ `mediaUrl` (visible si kind=VIDEO, validation URL)
   - Champ `previewImageUrl` optionnel
9. Cards templates : preview + edit + soft-delete + toggle active
10. Variables placeholder supportees dans `body` et `subject` : `{{patient.firstName}}`, `{{patient.lastName}}`, `{{intervention.name}}`, `{{cabinet.name}}`, `{{user.firstName}}` (commercial qui envoie)
11. Variables sont substituees au moment de l'envoi (cf EP09-S06), pas stockees evaluees

## Tests

- Test integration : CRUD complet (create, list, patch, soft-delete)
- Test integration : Zod refuse subject vide si kind=MAIL
- Test integration : soft-delete → isActive=false, le template n'apparait plus en list par defaut mais reste en BDD
- Test integration : tenant isolation — userTenantA ne peut pas lire templates de tenantB
- Test unit substitution variables : "Bonjour {{patient.firstName}}" + patient.firstName="Marie" → "Bonjour Marie"

## Notes techniques

- Service `lib/templateRenderer.ts` : fonction `renderTemplate(template, context) : { subject, body, mediaUrl }`
- Pas de moteur de templating lourd (Handlebars, etc.) — simple regex `{{path.to.field}}` → lookup
- Markdown rendu cote frontend uniquement (preview + display)
- Pas d'envoi reel (cf scope brief : pas d'envoi mail/whatsapp)
