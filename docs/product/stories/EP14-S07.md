## User story

En tant qu'**editeur**, je veux **un texte CGU non-HDS redige avec le contexte complet du projet**, afin de **couvrir juridiquement l'editeur et le cabinet sans bloquer le demarrage sur l'attente d'un juriste.**

---

## Contexte (decision + contexte charge pour la redaction)

**Decision (2026-06-01)** : on n'attend pas un juriste pour demarrer (constat : les juristes s'appuient eux-memes sur des outils type Claude). Le texte est redige avec le modele Opus, charge du contexte projet complet ci-dessous, puis une revue juriste est prevue ensuite et **n'est pas bloquante**.

**Contexte projet a injecter dans la redaction** :
- CRM Commercial = fork non-HDS de `crm-chirurgien` (ADR-0001).
- ADR-0002 : retrait du role CHIRURGIEN + des notes medicales.
- ADR-0003 : strategie non-HDS a 3 leviers — (1) retrait des donnees de sante, (2) **CGU consentement** (ce texte), (3) securite renforcee.
- ADR-0008 : projet jumeau commercial, hebergement cloud standard non-HDS.
- Positionnement produit : "on complete Doctolib / Qualimed, on ne remplace pas". Les donnees medicales restent dans Qualimed (DPI). Aucune donnee Art. 9 dans l'app.
- Relation : editeur (plateforme) <-> cabinet client (B2B). Le cabinet est responsable de traitement pour ses donnees commerciales.
- Point de depart existant : `docs/legal/CGU-clause-HDS-non-medical.md` (Art. X / Y / Z) + `docs/legal/MESSAGING-IN-APP-NON-HDS.md`.

## Acceptance Criteria (ce que le texte doit couvrir)

1. Interdiction explicite de saisir/stocker des donnees de sante (Art. 9 RGPD) dans l'app — clause centrale non-HDS.
2. Repartition des responsabilites : editeur (heberge + securise la plateforme) vs cabinet (responsable de traitement, s'engage a ne pas saisir de donnee de sante).
3. Finalites (gestion commerciale : pipeline, devis, paiement, relances) + bases legales associees.
4. Engagement de non-saisie de donnee de sante par le cabinet + consequences en cas de manquement.
5. Mentions : identite de l'editeur, droit applicable, modalites d'acceptation, version + date.
6. Articulation avec le gate (EP14-S02) : le texte alimente `cguVersion` ; une nouvelle version (ex : post-revue juriste) declenche un re-prompt force a l'acceptation.
7. Marqueur de transparence : "redige avec l'assistance de Claude, revue juriste a venir — ne constitue pas un avis juridique".
8. Passage du texte final dans `byan-hds-check` (verdict attendu OK : mentions sante en contexte d'interdiction).
