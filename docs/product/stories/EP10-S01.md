## User story

En tant que **developpeur**, je veux **modeliser un catalogue de templates PDF associables a une intervention ou a un label de document**, afin de **permettre au commercial de generer/envoyer des documents pre-rempli (lettres pre-op, ordonnances, formulaires)**.

## Acceptance Criteria

### Schema Prisma

1. Nouvelle table `DocumentTemplate` :
   - `id : UUID PK`
   - `tenantId : UUID FK Tenant`
   - `name : String` (ex "Lettre confirmation pre-operatoire")
   - `description : String?`
   - `kind : Enum DocumentTemplateKind` (PDF_UPLOADED | HTML_RENDERED)
   - `fileUrl : String?` (chemin vers le PDF source si kind=PDF_UPLOADED)
   - `bodyHtml : Text?` (template HTML avec variables si kind=HTML_RENDERED)
   - `variableSchema : Json?` (liste des variables attendues, ex `["patient.firstName", "intervention.name"]`)
   - `isActive : Boolean DEFAULT true`
   - `createdAt`, `updatedAt`
   - `@@unique([tenantId, name])`
   - `@@index([tenantId, isActive])`
2. Nouvel enum `DocumentTemplateKind` : `PDF_UPLOADED`, `HTML_RENDERED`
3. Nouvelle table `InterventionDocumentTemplate` (M:N intervention ↔ template) :
   - `id : UUID PK`
   - `interventionId : UUID FK Intervention` (cascade)
   - `documentTemplateId : UUID FK DocumentTemplate` (cascade)
   - `order : Int DEFAULT 0`
   - `createdAt`
   - `@@unique([interventionId, documentTemplateId])`
4. Nouveau champ `DocumentLabel.documentTemplateId : UUID? FK DocumentTemplate` (1:N — un label peut etre rempli via UN template defini)
   - `onDelete: SetNull` (la suppression d'un template ne casse pas les labels)

### Migration

5. Migration Prisma `add_document_templates` : cree les nouvelles tables + le champ FK sur DocumentLabel
6. Le seed ne change pas — les nouvelles tables sont vides au demarrage

### Logique metier

7. Validation Zod cote backend :
   - Si `kind=PDF_UPLOADED` → `fileUrl` requis, `bodyHtml` doit etre null
   - Si `kind=HTML_RENDERED` → `bodyHtml` requis, `fileUrl` doit etre null
   - `variableSchema` est optionnel, valide en `Array<string>` si present

## Tests

## Notes techniques

- Pas de champ `defaultPath` dans `DocumentTemplate` — toute upload va dans `{tenantId}/templates/{uuid}.pdf` (pattern Multer existant)
- `variableSchema` est purement informatif au MVP (utilise pour l'UI de l'editeur), pas de validation runtime des variables presentes dans `bodyHtml`
- Au niveau du DocumentLabel, le `documentTemplateId` indique "ce label peut etre genere/distribue via ce template" — utile pour l'UI documents (afficher un bouton "Generer le PDF a partir du template")
