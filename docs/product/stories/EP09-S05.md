# EP09-S05 — Binding intervention → MessageTemplate (par sub-stage)

> **HDS-CHECK** (2026-05-18) — Verdict : `OK avec rename`
> Periode : NON-HDS (cf. ADR-0008 du repo source)
> Mots-cles BLOCKED detectes : aucun
> Mots-cles SUSPECT detectes : "patient" (preferer "client"), "intervention" (preferer "prestation"), "mammoplastie" (exemple a remplacer)
> Action : rename requis
> Justification : table de jointure intervention-template-substage. Schema technique, l'exemple "mammoplastie" est a remplacer par un libelle commercial neutre.

**Epic** : Follow-up dedie • **Priorite** : Must have • **Estimation** : 2h

## User story

En tant que **administrateur**, je veux **associer un MessageTemplate a une intervention pour un sous-stage donne**, afin que **les commerciaux voient automatiquement les templates pertinents pour le patient en cours** (ex : video J+3 specifique a la mammoplastie).

## Acceptance Criteria

### Schema Prisma

1. Nouvelle table `InterventionMessageTemplate` :
   - `id : UUID PK`
   - `interventionId : UUID FK Intervention` (cascade delete)
   - `messageTemplateId : UUID FK MessageTemplate` (cascade delete)
   - `targetSubStage : FollowupSubStage?` (NULL = applicable a tous les sub-stages)
   - `order : Int DEFAULT 0`
   - `createdAt`
   - `@@unique([interventionId, messageTemplateId, targetSubStage])`
   - `@@index([interventionId])`
   - `@@index([messageTemplateId])`

### API

2. Routes :
   - `GET /api/interventions/:id/message-templates` retourne les templates lies (tries par `targetSubStage` puis `order`)
   - `POST /api/interventions/:id/message-templates` body `{ messageTemplateId, targetSubStage?, order? }`
   - `DELETE /api/interventions/:id/message-templates/:bindingId`
   - `PATCH /api/interventions/:id/message-templates/:bindingId` (re-order ou changer targetSubStage)
3. Routes ADMIN only

### UI Parametrage

4. Sur la page edition d'une `Intervention` :
   - Section "Messages de relance" sous la section "Documents requis" (existant)
   - Tableau avec colonnes : `templateName | kind | targetSubStage | actions`
   - Bouton "+ Lier un template" → dialog avec select `messageTemplate` + select `targetSubStage` (option "Tous les sub-stages")
   - Drag pour re-order au sein d'un meme `targetSubStage`
5. Pre-filtrage : seuls les templates `isActive=true` apparaissent dans le select

### UI Follow-up

6. Sur la `FollowupView` (page /follow-up), au survol d'une card :
   - Tooltip ou icone qui montre "X templates disponibles pour ce patient" (count des templates dont `interventionId IN process.interventions` ET `targetSubStage IN (NULL, process.followupSubStage)`)
7. Le ProcessPanel onglet "Suivi" (de EP09-S03) affichera la liste des templates pertinents (cf EP09-S06 pour l'envoi)

## Tests

- Test integration : POST binding cree la jointure, GET intervention retourne les templates
- Test integration : un patient avec intervention X et substage J3 voit les templates de X bindes a J3 OU sans targetSubStage
- Test integration : DELETE intervention cascade les bindings
- Test integration : DELETE messageTemplate cascade les bindings (ou les laisse orphelins si on choisit setNull — choisir cascade par simplicite)

## Notes techniques

- Service helper : `getRelevantTemplates(processId) : MessageTemplate[]` qui groupe par sub-stage et applique le filtre
- Pas de calcul cote DB (pas de view) — le helper fait un join Prisma + filter en TS
