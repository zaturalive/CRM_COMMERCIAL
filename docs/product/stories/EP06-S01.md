# EP06-S01 — Checklist documents + statuts + auto-ajout

**Epic** : Documents • **Priorite** : Must have • **Estimation** : 3h

## User story

En tant que **commercial**, je veux **voir la checklist des documents pre-operatoires auto-remplie** selon les interventions du process, afin de **ne rien oublier de demander au patient**.

## Acceptance Criteria

### Auto-ajout (hook backend)

1. Hook `syncProcessDocuments(processId)` (cf. stacks/backend.md §5.1) :
   - Appele apres `POST /api/processes/:id/devis`, `POST /api/processes/:id/devis-interventions`, `PATCH /api/devis-interventions/:id`
   - Pour chaque `DevisIntervention` actif, lire les `InterventionDocumentLabel` de l'intervention
   - Pour chaque label, creer un `ProcessDocument` si inexistant (couple processId + documentLabelId)
   - **Ne touche pas** aux `ProcessDocument` existants (preserver statuts/fichiers)
2. Les `ProcessDocument` copient le `name` du `DocumentLabel` a la creation (snapshot)

### UI Onglet Documents

3. Onglet "Documents" du Process Panel
4. `<DocumentProgressBadge />` large (X/Y + %) en haut
5. Liste `<DocumentRow />` par document :
   - Icone Lucide File + nom + pastille statut + actions
   - Statuts : `EN_ATTENTE` (gris) → `RECU` (bleu) → `VALIDE` (vert)
   - Clic pastille → avance d'un cran (scale 1.2 → 1 anim)
6. Bouton `+ Ajouter un document` manuel (sans label)
7. Actions par document : Eye (preview), Download, Upload, Trash2 (cf. EP06-S02)
8. Endpoints CRUD : `GET/POST/PATCH/DELETE /api/processes/:id/documents[/:dId]`

## Tests

- Test unit : `syncProcessDocuments` idempotent (2 appels → pas de duplicats)
- Test unit : ajouter intervention → nouveaux docs, modifier statut → preserver au prochain sync
- Test integration : creer devis → ProcessDocument crees pour tous les labels des interventions
