# EP12-S02 — DevisBuilder optimistic recompute (fix refresh 2s)

> **HDS-CHECK** (2026-05-18) — Verdict : `OK avec rename`
> Periode : NON-HDS (cf. ADR-0008 du repo source)
> Mots-cles BLOCKED detectes : aucun
> Mots-cles SUSPECT detectes : "clinique" (OK contexte logistique)

> Justification : refactor UI calcul local pour eviter le refresh 2s. Story technique, vocabulaire residuel "clinique" reste en contexte logistique.

**Epic** : UI performance — optimistic updates • **Priorite** : Must have • **Estimation** : 4h

## User story

En tant que **commercial**, je veux **que la modification d'un champ du devis (prix, clinique, date, options) ne declenche plus un spinner de 2s avant de voir le nouveau total**, afin de **construire un devis sans cassure de flux**.

**Diagnostic du bug actuel** : `DevisBuilder.tsx` L226-230 → `refresh()` apres chaque mutation. `refresh()` fait `setSaving(true)` puis `Promise.all([loadDevis(), loadTotal()])`. Le `setSaving(true)` ajoute un texte "· Enregistrement…" (mineur) mais surtout le `loadDevis` re-mounte tous les sub-components (`InterventionRow`, `CommercialRow`, `StayCard`) parce qu'ils utilisent `defaultValue` (uncontrolled) avec re-key sur l'objet parent. Resultat : tous les inputs perdent le focus + 1-2s de blocage.

## Acceptance Criteria

### Strategie globale

1. Adopter un **shadow optimistic state** dans `DevisBuilder` :
   - State local `optimisticDevis : Devis | null` qui mirror `devis`
   - Mutations PATCH appliquent immediatement sur `optimisticDevis` (calcul local du delta)
   - Refetch background reconcilie sans re-key (assigne props champ par champ pour conserver les refs React)
2. `loadDevis({ silent: boolean })` : ne fait plus `setLoading(true)` sur les refetches
3. `loadTotal({ silent: boolean })` : ne fait plus `setSaving(true)` sur les refetches optimistic
4. Le total `calc` est recalcule localement quand possible (cf. §calcul local)

### Calcul local du total

5. Helper `lib/optimistic/computeDevisTotalOptimistic.ts` :
   - Reproduit le calcul du backend `services/devisCalculator.ts` cote frontend
   - Inputs : `devis`, `cliniques`, `cliniqueTarifs`, `cliniqueOptions`
   - Output : `Calculation` (meme shape que le backend)
   - Tests d'equivalence : pour 10 devis seed, le frontend doit retourner le **meme** total au centime que le backend
6. Endpoint `GET /api/cliniques/:id/tarifs` (peut deja exister) — sinon ajouter pour permettre le calcul local
7. Les endpoints `cliniques` + `tarifs` + `options` sont mis en cache cote frontend (state) et invalides uniquement quand le ADMIN modifie le parametrage (rare en cours d'utilisation)

### Optimistic mutations

8. Refactor `runMutation()` dans `DevisBuilder.tsx` :
   - Avant `apiFetch`, applique l'effet du PATCH sur `optimisticDevis` (mutation locale)
   - Recompute `calc` local
   - Lance `apiFetch`
   - Si succes : `loadDevis({ silent: true })` + `loadTotal({ silent: true })` en background
   - Si echec : revert l'`optimisticDevis` a son etat avant le PATCH + toast erreur
9. Patterns de PATCH supportes optimistically (priorite) :
   - `patchIntervention({ duration })` : update `optimisticDevis.devisInterventions[i].duration`
   - `patchIntervention({ cliniqueId })` : update + recompute groupes
   - `patchIntervention({ dateIntervention })` : update + recompute groupes
   - `patchFee({ price | quantity | isIncluded })` : update fee
   - `toggleOption()` : add/remove option
   - `patchCustomOption({ price | quantity })` : update
   - `patchStay({ mode | nightCount })` : update

### UX details

10. La barre `Sticky total` reflete instantanement les nouveaux montants (via `calc` local)
11. L'animation `bounceTotal` se declenche sur changement de `calc.total` (deja en place)
12. En cas de divergence local/serveur (rare, ex bug calcul), un toast warning "Total mis a jour serveur" + reload

## Tests

- Test unit `computeDevisTotalOptimistic` : equivalence avec backend pour 10 cas (incluant anti-doublon, sejours nuits, options custom)
- Test E2E Playwright : changer prix d'un fee → total se met a jour en < 100ms (sans spinner)
- Test E2E : changer clinique → total se met a jour en < 100ms (frais bloc/anesthesie recalcule)
- Test E2E : input perd PAS le focus apres mutation
- Test integration : si le backend rejette un PATCH (Zod prix negatif), le `runMutation` revert le local

## Notes techniques

- Risque : duplication de logique frontend/backend pour le calcul → mitigation par tests d'equivalence stricts
- Alternative (V1) : remplacer le calcul backend par un endpoint qui retourne aussi le calc d'un "preview" sans persister — V1 only, pas au MVP
- Les inputs uncontrolled actuels (defaultValue) restent — c'est OK car le `loadDevis({ silent: true })` ne re-mount plus les rows (state local prime)
- Reordonner les hooks : `optimisticDevis` est la source de verite affichee, `devis` (server) sert de fallback initial
