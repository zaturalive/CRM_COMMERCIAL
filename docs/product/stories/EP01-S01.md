## User story

En tant que **utilisateur d'un cabinet**, je veux **me connecter sur le sous-domaine dedie a mon cabinet** afin que mes donnees soient **isolees de celles des autres cabinets**.

---

## Contexte

Fondement de toute la securite. Chaque cabinet a un sous-domaine (`cabinet-delobaux.crm.local`). Le backend resout le tenant, signe un JWT, et toutes les requetes suivantes sont filtrees au niveau ORM.

Reference : CDCT v1.5 §2.3, ADR-0005 tests securite.

---

## Acceptance Criteria

1. La page `/login` affiche le nom du cabinet (extrait du sous-domaine) et un formulaire email + password
2. Submit valide → POST `/api/auth/login` → JWT signe avec `{ userId, tenantId, role, exp }`
3. JWT stocke cote NextAuth (session cookie HTTP-only)
4. Les API calls suivants envoient `Authorization: Bearer <jwt>` automatiquement
5. Backend : middleware `requireJWT` verifie la signature, 401 si invalide ou expire
6. Backend : middleware `requireTenant` injecte un Prisma extended client qui filtre `tenantId` sur toutes les requetes
7. Un User de tenant A qui tente d'acceder a une ressource de tenant B recoit un **404** (pas 403 — eviter enumeration)
8. `/api/auth/me` renvoie `{ userId, email, tenantId, role, firstName, lastName }`
9. Logout clear la session cookie et redirige `/login`
10. Rate limit sur `/api/auth/login` : 10 tentatives / 15 min / IP

## Notes techniques

- Tables touchees : `Tenant`, `User` (cf. data-model.md §2.1, §2.2)
- Lib : NextAuth v5 (frontend), jsonwebtoken + bcryptjs (backend)
- Password hash : bcrypt rounds 10
- JWT expires in : 7 jours
- Secret JWT : `process.env.JWT_SECRET` (min 32 bytes)
- Prisma extended client : voir stacks/backend.md §3.2
