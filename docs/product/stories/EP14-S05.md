## User story

En tant qu'**editeur / DPO**, je veux **chiffrer au repos les colonnes sensibles**, afin qu'**un acces non autorise au dump Postgres ou au volume disque ne revele pas les donnees clients ni les secrets d'authentification**.

---

## Contexte

**Etat verifie (audit code 2026-06-01)** : **AUCUN** chiffrement at-rest. Pas d'extension `pgcrypto`, pas de chiffrement app-level (`encrypt/decrypt`) sur les colonnes sensibles. Les mots de passe sont hashes bcrypt (`seed.ts:185`) mais c'est tout.

**Lien avec 2FA (EP14-S01)** : le secret TOTP (`User.totpSecret`) doit etre chiffre at-rest. **Decision Q3 (2026-06-01)** : 2FA part en degrade avec **chiffrement app-level** du secret TOTP (cle via env/KMS) ; cette story livre ensuite la solution propre (pgcrypto) et migre les secrets existants.

**Deux options (a trancher dans la story)** :
- **Option A — app-level** : chiffrement AES-256-GCM cote backend, cle geree par env/KMS Scaleway. Portable, independant du SGBD, mais la cle vit cote app.
- **Option B — pgcrypto** : chiffrement cote Postgres (`pgp_sym_encrypt`). Centralise au SGBD, mais couple a Postgres + gestion de la cle en base/connexion.

---

## Acceptance Criteria

1. Choix documente Option A vs B (recommandation par defaut : **A app-level AES-256-GCM** pour rester portable PaaS, cle hors-base).
2. Colonnes chiffrees at-rest : `User.totpSecret`, `Client.email`, `Client.phone`, `Process.noteCommerciale` (liste alignee checklist S2 — a confirmer selon sensibilite).
3. Migration de chiffrement des donnees existantes (back-fill) sans perte.
4. Lecture/ecriture transparente cote service (helper `encryptField` / `decryptField` ou middleware Prisma `$extends`).
5. Gestion de cle documentee : rotation possible, cle non commitee, source = env/KMS.
6. Test : un `pg_dump` ne revele pas les colonnes chiffrees en clair.
7. Compatibilite recherche : si une colonne chiffree doit rester recherchable (ex email login), prevoir un index deterministe ou un hash de recherche separe (a arbitrer — impact UX login).

---

## Tests de securite (obligatoires)

- [ ] `pg_dump` → les colonnes chiffrees ne sont pas lisibles en plain text
- [ ] Ecriture puis lecture d'un champ chiffre → valeur identique cote app (round-trip)
- [ ] Secret TOTP migre depuis le degrade app-level sans invalider les 2FA existantes
- [ ] Cle absente / invalide → echec controle (pas de lecture silencieuse en clair)
- [ ] Login par email reste fonctionnel (selon strategie de recherche retenue)

Fichier cible : `apps/backend/tests/security/at-rest-encryption.test.ts`

## Notes techniques

- **App-level** : `node:crypto` AES-256-GCM, IV par valeur, format `v1:iv:tag:ciphertext`.
- **Prisma** : encapsuler via `$extends` (result/query) pour transparence, ou helpers explicites aux points d'acces.
- **Alternative infra** : volume Scaleway chiffre (LUKS/managed) couvre le "vol de disque" mais PAS le "dump applicatif" — les deux sont complementaires. Le volume chiffre = infra, hors cette story.
