# EP03-S02 — Page Fiche Client dediee

**Epic** : Fiche Client • **Priorite** : Must have • **Estimation** : 3h

## User story

En tant que **commercial ou chirurgien**, je veux **une page dediee par client** affichant son historique de process et ses devis, afin d'avoir **une vision 360** avant chaque interaction.

## Acceptance Criteria

1. Route `/clients/[id]` — page dediee (pas un modal)
2. **Header** (liquid glass full-width) :
   - Avatar rond 72×72 (initiales)
   - Nom Prenom (DM Sans 22px 700)
   - Infos personnelles copiables : telephone, email, ville, source d'acquisition
   - CA total cumule (DM Sans 28px mono, aligne a droite)
3. **Stats** (grid 3 cols, cartes liquid glass) :
   - Process actifs (nombre)
   - Devis signes (nombre)
   - Intensite moyenne (mono, ex `7.2/10`)
4. **Zone principale (70%)** — Historique process :
   - Liste chronologique desc
   - Chaque ligne : ref + intervention(s) principale(s) + date + badges (stage + docs X/Y + acompte paye)
   - Border-left 4px couleur du stage
   - Clic → ouvre le **Process Panel** (voir EP04-S04)
   - Hover : scale 1.01 + shadow-md
5. **Colonne droite (30%)** — Panneau devis (voir EP03-S03)
6. Endpoints : `GET /api/clients/:id`, `GET /api/clients/:id/processes`, `GET /api/clients/:id/devis`

## Tests

- Test integration : client avec 3 process retourne 3 historique items
- Test badge docs : ProcessDocument `status = VALIDE` compte dans le X

## Notes techniques

- Composants : `<ClientProfilePage />`, `<ClientProcessHistoryItem />` (cf. frontend.md)
- Stats calculees cote backend dans `GET /api/clients/:id`
- Le CA total = somme des `Devis.totalCached` signes + payes du client
