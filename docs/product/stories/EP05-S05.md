# EP05-S05 — Options contextuelles clinique + anti-doublon

**Epic** : Devis • **Priorite** : Must have • **Estimation** : 3h

## User story

En tant que **commercial**, je veux **que les options catalogue affichees correspondent a la clinique choisie**, et que **les frais et options soient mutualises si plusieurs interventions sont a la meme clinique le meme jour**, afin de **ne pas facturer 2× la meme chose**.

## Acceptance Criteria

### Options contextuelles

1. `<ClinicContextualOptions />` sous chaque intervention du devis commercial
2. Au choix clinique, fetch `/api/cliniques/:id/options` (actives uniquement)
3. Checkboxes pour chaque option catalogue, prix a droite mono
4. Changement de clinique → fade-out anciennes options → fade-in nouvelles
5. Snapshot : cochage cree un `DevisOption` avec label + price copies

### Anti-doublon

6. Grouper les `DevisIntervention` par `(cliniqueId, dateIntervention)` cote front
7. Si plusieurs interventions du meme groupe :
   - **Une seule section** "Options catalogue" par groupe (pas une par intervention)
   - Badge "Frais mutualises" visible (vert) avec tooltip
   - Les options cochees s'appliquent au groupe
8. Calcul backend (formule CDCT §6.3) :
   - Frais bloc + anesthesie : une fois par groupe, sur duree cumulee
   - Frais sejour : une fois par groupe (via `DevisStay`)
   - Options cochees : une fois par groupe

### Custom options (EP05-S06 mais pose les bases)

9. Chaque `DevisOption` lie a un devis a une `stayKey = cliniqueId-YYYY-MM-DD` (computed cote serveur) pour permettre le groupage d'affichage

## Tests

- Test backend : 2 `DevisIntervention` meme clinique + meme jour → calcul frais bloc une fois
- Test unit : calcul avec 1 clinique sur 2 jours differents → 2 groupes, 2× frais
- Test front : changement clinique → options desaffichees

## Notes techniques

- Pas de nouvelle table. `DevisOption.stayKey` calcule a l'insertion (redondance controlee pour perf)
- Source : CDCT §6.5 "logique d'affichage suffit"
