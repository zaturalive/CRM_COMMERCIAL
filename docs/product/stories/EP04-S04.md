## User story

En tant que **utilisateur**, je veux **un panneau lateral centralisant toutes les actions d'un process** avec un fil d'Ariane pour me deplacer entre les etapes, afin de **ne plus naviguer entre plusieurs pages**.

## Acceptance Criteria

### Structure

1. Sheet 720px slide-in 200ms depuis la droite (shadcn `<Sheet />`)
2. Ouverture au clic carte pipeline OU ligne historique fiche client
3. URL hash : `?process=<id>` pour partage
4. Fermeture : backdrop click, bouton X, Escape
5. Layout : Header + Tabs + Content scrollable + Footer

### Header

6. Nom patient + reference process (copiable)
7. **`<ProcessStepper />`** — 5 etapes cliquables :
   - Cercle 32×32 avec icone Lucide + label
   - Etats : Passee (emerald + Check), Active (accent + shadow), Future (gris outline)
   - Hover : scale 1.05 + tooltip "Deplacer vers [etape]"
   - Clic : PATCH `/api/processes/:id/stage` avec `targetStage`
8. **2 sorties secondaires** sous le stepper :
   - Follow-up (amber, Lucide Clock)
   - Non qualifie (rouge, Lucide XCircle)
   - Discretes (hauteur 28px, opacity 0.6 → 1 hover)
   - Clic → dialog raison obligatoire
9. **`<StageContextBanner />`** — bandeau colore avec message action prioritaire selon stage (cf. design spec §6.3 table)

### Tabs (4 onglets)

10. Tabs : Vue d'ensemble | Notes | Documents | Devis
11. Point accent sur l'onglet prioritaire selon stage :
    - Contact → Vue
    - Consultation → Notes (chir) / Vue (comm)
    - Post-consult → Devis
    - Confirmee → Documents
    - Op programmee → Vue (barre paiement)

### Transitions

12. Clic etape future : si transition valide → deplacement immediat (200 OK)
13. Si invalide (422 retour back) : dialog de confirmation avec raison + bouton "Forcer" (`force: true`)
14. Animations : pulse cercle 1.1 → 1 + fade-in contenu 200ms

### Footer

15. Actions rapides (doublon accessible du fil d'Ariane) :
    - Primary `→ Confirmee` (si stage Post-consult)
    - Secondary `→ Follow-up`
    - Secondary `→ Non qualifie`

## Tests

- Test : clic etape future Consultation sans date consult → dialog 422
- Test : clic sortie Follow-up → dialog raison → PATCH avec raison → process dans section
- Test : reouverture via URL `?process=<id>` → panel ouvert sur bon process
