## User story

En tant qu'**ADMIN de cabinet**, je veux **accepter explicitement les CGU (dont l'interdiction de stocker des donnees de sante) avant tout usage**, afin que **l'editeur et le revendeur soient juridiquement couverts en periode non-HDS** (consentement commercial Art. 9.2.a RGPD).

---

## Contexte

**Etat verifie (audit code 2026-05-29)** : acceptance CGU **ABSENTE** — aucun champ `cguAcceptedAt / cguVersion` sur `Tenant` (`schema.prisma`), aucune route `/onboarding`, aucun middleware de gate. Le `middleware.ts` front est **NextAuth-only** (pas de redirect conditionnel). Le texte CGU existe : `docs/legal/CGU-clause-HDS-non-medical.md` (Art. X / Y / Z).

**C'est le seul des 3 sujets qui protege juridiquement des ce soir** (vs 2FA et sous-domaine). ADR-0003 : 3 leviers non-HDS = retrait donnees sante (fait), **CGU consentement (cette story)**, securite renforcee (partielle).

**Dependance dure (CDCF D7, L.222 — BLOQUANT)** : le texte CGU doit etre **valide par un juriste** avant integration. Si non valide : option de repli = deployer en `cguVersion: "1.0-draft"` avec re-prompt force a la version validee (RM5). **A trancher avec Florian.**

---

## Acceptance Criteria

1. Migration Prisma : `Tenant.cguAcceptedAt DateTime?`, `Tenant.cguVersion String?`, `Tenant.cguSignatoryName String?`.
2. Middleware (front `middleware.ts` + garde back) : si `cguAcceptedAt == null` → redirect `/onboarding/cgu`. Exemptions : `/login`, `/onboarding/cgu`, `/api/auth/*`, `/api/tenant/accept-cgu`.
3. Page `/onboarding/cgu` plein-ecran : bandeau non-HDS + texte integral Art. X / Y / Z + champ « Nom complet du signataire » (saisi, pas pre-rempli de force — RM4) + date du jour (lecture seule) + checkbox obligatoire + bouton « Accepter et continuer » (disabled tant que non coche) + « Annuler » → logout.
4. `POST /api/tenant/accept-cgu` body `{ signatoryName, cguVersion }` : valide ADMIN du tenant courant + `cguVersion` connue + `signatoryName` non vide → set `cguAcceptedAt = now()` (UTC), `cguVersion`, `cguSignatoryName`.
5. RBAC (RM1) : **seul un ADMIN** peut accepter. COMMERCIAL arrivant sur la page (CGU non acceptee) → message « contactez votre administrateur » + logout (A1).
6. Apres acceptation → JWT/session rafraichis (flag `cguAccepted: true`) → redirect `/dashboard`.
7. Banniere de rappel non-HDS persistante 7 jours sur le dashboard.
8. Trace immuable de l'acceptation (preuve litige RGPD — RM3) : a minima la ligne `Tenant` (timestamp + version + signataire) ; ideal = entree `AuditLog` (EP14-S04).
9. (Optionnel D7) page admin `/admin/cgu-history` pour que Florian voie le statut CGU par cabinet.

## Tests de securite (obligatoires)

- [ ] ADMIN se logue → redirect `/onboarding/cgu` → coche + signe → arrive `/dashboard`
- [ ] COMMERCIAL se logue (CGU non acceptee) → message contacter admin, pas d'acces
- [ ] Bypass : acces direct `/dashboard` sans CGU → re-redirect `/onboarding/cgu`
- [ ] Non-ADMIN appelle `POST /api/tenant/accept-cgu` → 403
- [ ] `cguVersion` inconnue (tentative downgrade) → 400
- [ ] Cross-tenant : un ADMIN ne peut accepter la CGU d'un autre tenant → 404/403
