## User story

En tant qu'**editeur**, je veux **consulter et filtrer les logs d'audit de l'app depuis le Back Office**, afin de **diagnostiquer un incident, suivre l'activite et reperer un usage anormal.**

---

## Contexte

**Dependance directe** : cette story consomme les donnees produites par **EP14-S04** (middleware d'audit append-only). EP14-S04 = production des logs ; EP17-S05 = lecture/analyse. Sans EP14-S04 livre, il n'y a rien a afficher.

**Etat verifie (audit code 2026-06-01)** : aucun modele `AuditLog`, donc aucune vue. A construire apres (ou avec) EP14-S04.

---

## Acceptance Criteria

1. `GET /api/admin/audit-logs` (editeur) : liste paginee des entrees `AuditLog`, avec filtres : tenant, userId, methode, path, plage de dates, statusCode.
2. Recherche + tri (par date) + pagination (volume potentiellement eleve).
3. Vue detail d'une entree (tous les champs : qui/quoi/ou/comment/quand + bodyHash).
4. Cross-tenant : l'editeur voit les logs de tous les tenants ; un ADMIN de cabinet n'accede pas a cette vue (BO reserve editeur — EP17-S01).
5. Lecture seule : aucune route de modification/suppression de log exposee (append-only respecte cote API).
6. Indicateurs simples : nombre de mutations par tenant, echecs de login, pics d'activite (agregats basiques, sans sur-conception — Mantra #37).
7. Export possible (CSV/JSON) d'un sous-ensemble filtre.

---

## Tests de securite (obligatoires)

- [ ] Editeur accede a `/api/admin/audit-logs` → liste filtrable, cross-tenant
- [ ] ADMIN de cabinet appelle la route → 403
- [ ] COMMERCIAL → 403
- [ ] Aucune route n'expose un DELETE/UPDATE sur les logs (append-only verifie)
- [ ] Les logs affiches ne revelent pas de donnee metier en clair (coherent avec la sanitization EP14-S04)

Fichiers cibles : `apps/backend/tests/security/audit-log-viewer.test.ts` + e2e `/admin/logs`

## Notes techniques

- **Index DB** : prevoir des index sur `tenantId`, `occurredAt`, `userId` pour des filtres reactifs sur un gros volume.
- **Pagination** : keyset/cursor plutot qu'offset si le volume grossit.
- **Agregats** : commencer par des comptages simples ; brancher un outil d'observabilite plus riche est du ressort infra (monitoring), hors cette story.
