# EP04-S05 — Notes commerciale + medicale avec droits role-based

> **HDS-CHECK** (2026-05-18) — Verdict : `BLOCKED`
> Periode : NON-HDS (cf. ADR-0008 du repo source)
> Mots-cles BLOCKED detectes : "note medicale", "noteMedecin", "confidentiel medical"
> Mots-cles SUSPECT detectes : "chirurgien", "commercial"
> Action : report HDS
> Justification : cas canonique du skill (§7.4) — un champ texte libre destine a recueillir des observations medicales du praticien constitue une donnee Art. 9 RGPD. Solutions : (a) retirer le champ noteMedecin du repo non-HDS, (b) le renommer notePraticien avec clause contractuelle interdisant tout contenu medical + check + formation user.

**Epic** : Pipeline & Process • **Priorite** : Should have • **Estimation** : 1.5h

## User story

En tant que **chirurgien**, je veux **ecrire des notes medicales invisibles au commercial** et en tant que **commercial** je veux **mes notes commerciales invisibles au chirurgien**, afin de **separer le confidentiel medical et les infos commerciales**.

## Acceptance Criteria

1. Onglet "Notes" du Process Panel affiche 2 textareas :
   - **Note commerciale** : editable par COMMERCIAL, **masquee entierement** au CHIRURGIEN
   - **Note medicale** : editable par CHIRURGIEN, lecture seule pour COMMERCIAL (encadre gris + Lucide Lock)
2. Route backend `PATCH /api/processes/:id/notes` :
   - Body `{ noteCommerciale }` : autorise COMMERCIAL uniquement → 403 sinon
   - Body `{ noteMedecin }` : autorise CHIRURGIEN uniquement → 403 sinon
3. GET process :
   - Reponse pour COMMERCIAL inclut `noteMedecin` (lecture)
   - Reponse pour CHIRURGIEN **exclut** `noteCommerciale` (champ omis du JSON)
4. Auto-save debounced 2s

## Tests

- Test securite : CHIR GET process → JSON sans `noteCommerciale`
- Test securite : COMM PATCH `{ noteMedecin }` → 403
- Test securite : CHIR PATCH `{ noteCommerciale }` → 403
