# EP16-S01 — Refonte rendu PDF devis (mentions legales commerciales + mise en page)

> **HDS-CHECK** (2026-06-01) — Verdict : `OK avec vigilance`
> Periode : NON-HDS (cf. ADR-0003)
> Mots-cles BLOCKED detectes : aucun dans la story ; **a surveiller a l'implementation**
> Mots-cles SUSPECT : le PDF devis du repo source contenait des elements medicaux (consentement libre et eclaire, frais anesthesiste, separation frais cliniques medicaux). Ces elements sont **BLOCKED / hors-scope non-HDS**.
> Action : implementable pour le **versant commercial uniquement**. L'implementeur doit faire passer le contenu final du template PDF dans `byan-hds-check` avant livraison.
> Justification : le devis commercial porte prestation + honoraires + mentions legales commerciales. Aucune donnee Art. 9 tant que les elements medicaux ci-dessus ne sont pas reintroduits.

**Epic** : EP16 — Devis/PDF commercial utilisable
**Priorite** : P0 go-live
**Estimation** : 1.5 - 2 j
**Statut** : Planned (scope confirme 2026-06-01)
**UC de reference** : `docs/uc/UC-37-devis-pdf.md`

---

## User story

En tant qu'**utilisateur commercial**, je veux **un PDF de devis lisible et legalement correct**, afin de **pouvoir l'envoyer a un client sans avoir honte du rendu**.

---

## Contexte

**Retour terrain** : le PDF est juge "nul" (Dimitry 2026-06-01) et "inutilisable en l'etat" (feedback Cecillia 2026-05-28) : mentions legales manquantes, mise en page faible. Cote commercial 2026-05-27 : le PDF est un point de friction eleve.

**Etat technique** : le PDF existe (EP05-S07, rendu Puppeteer). Il s'agit d'une **refonte du rendu**, pas d'une creation.

**Scope (decision Q2 2026-06-01)** : "fix utilisable" — rendu + mentions legales commerciales + mise en page. **Hors vague (V1.1)** : preview PDF live pendant l'edition, mode brouillon, wizard 3 etapes.

**Garde-fou HDS** : on ne reintroduit AUCUN element medical (consentement medical, frais anesthesiste, separation frais cliniques medicaux, 2 signatures legales chirurgicales). Versant commercial seulement.

---

## Acceptance Criteria

1. Mentions legales commerciales presentes : identite de l'editeur/cabinet (raison sociale, SIRET si applicable), coordonnees, numero de devis, date d'emission, **duree de validite**, reference aux CGV.
2. Mise en page propre : en-tete cabinet, tableau des prestations lisible (libelle, quantite, prix unitaire, total), sous-totaux, total TTC, zone de signature commerciale.
3. Retrait des elements de surcharge signales : bouton/zone "copier le devis complet en texte" juge inutile (feedback Cecillia §Devis + §5).
4. Aucun champ medical dans le template (verifie par `byan-hds-check` sur le rendu final).
5. Le PDF reste genere cote backend (Puppeteer existant), sans regression sur la generation actuelle.
6. Compatibilite avec le champ remise (EP16-S02) : le PDF affiche la remise quand elle existe.
7. Donnees variables correctement substituees (client, prestations, montants) — pas de placeholder residuel.

---

## Tests (obligatoires)

- [ ] Generation PDF d'un devis complet → mentions legales commerciales presentes
- [ ] Le contenu du template ne contient aucun mot-cle medical (`byan-hds-check` vert)
- [ ] Montants et sous-totaux du PDF = montants calcules cote app (coherence)
- [ ] Devis avec remise (EP16-S02) → remise affichee correctement
- [ ] Non-regression : la route de generation actuelle reste fonctionnelle

Fichiers cibles : `apps/backend/tests/...devis-pdf.test.ts` + revue visuelle du template
