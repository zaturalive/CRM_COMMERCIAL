## User story

En tant qu'**editeur**, je veux **creer, consulter, modifier et suspendre des cabinets (tenants) depuis le Back Office**, afin de **gerer le parc de clients sans passer par le seed.**

---

## Contexte

**Etat verifie (audit code 2026-06-01)** : la creation de tenant se fait uniquement par le seed (`apps/backend/prisma/seed.ts`). Aucune route ni UI de gestion des tenants.

**Decision (Q1 2026-06-01)** : modele editeur + admin. L'editeur cree le cabinet + son premier compte ADMIN ; l'admin gere ensuite ses propres comptes (EP15-S02).

**Reconciliation** : cette story absorbe et remplace l'ancienne EP15-S01 (provisioning cabinet), desormais superseded.

---

## Acceptance Criteria

1. `POST /api/admin/tenants` (editeur) : cree un `Tenant` (slug, nom) + le premier compte ADMIN (email, nom) avec mot de passe temporaire + `mustChangePassword = true` (EP15-S04).
2. `GET /api/admin/tenants` + `GET /api/admin/tenants/:id` : liste + detail (nom, slug, statut, nb users, date creation).
3. `PATCH /api/admin/tenants/:id` : modifier nom + statut (`ACTIVE` | `SUSPENDED`).
4. Suspension : un tenant `SUSPENDED` refuse le login de ses users, **sans suppression de donnees**.
5. Suppression : par defaut on privilegie la suspension/archivage plutot que le delete dur (un delete = perte de donnees client + sujet RGPD). Si delete dur, alors : confirmation forte + audit + restriction editeur.
6. Validation : slug unique, format slug (tirets, pas d'underscore — RFC 1035), email valide.
7. UI BO : page `/admin/cabinets` (liste + creation + edition + suspension).
8. Toutes les actions tracees (EP14-S04, degradable).

## Tests de securite (obligatoires)

- [ ] Editeur cree un cabinet + 1er admin → tenant et compte crees, scope correct
- [ ] Non-editeur appelle `POST /api/admin/tenants` → 403
- [ ] Slug en double → 409/400, pas de creation partielle
- [ ] Tenant suspendu → login refuse a ses users, donnees conservees
- [ ] Delete dur (si implemente) → confirmation + audit + reserve a l'editeur
- [ ] L'isolation entre cabinets reste intacte (un tenant ne voit pas l'autre)

Fichiers cibles : `apps/backend/tests/security/tenant-crud.test.ts` + e2e `/admin/cabinets`
