# EP10-S04 — Envoi manuel template sur un process (genere PDF rempli)

> **HDS-CHECK** (2026-05-18 / MAJ 2026-05-20 — P3) — Verdict : `OK avec mitigation`
> Periode : NON-HDS (cf. ADR-0008 du repo source + ADR-0002 du repo commercial)
> Mots-cles SUSPECT restants : "patient" → "client", "intervention" → "prestation" (P4 Sprint).
> Mitigation P3 appliquee :
> 1. La mitigation amont sur EP10-S01 + EP10-S02 (templates commerciaux uniquement, variables whitelist, modal HDS, CGU) **garantit** que le PDF rendu est commercial.
> 2. **Modal HDS de consentement avant upload** dans `DocumentsTab.tsx` reste actif y compris pour l'action "Generer et attacher" — meme principe que l'upload manuel.
> 3. Le `ProcessDocument.fileUrl` herite des memes regles d'audit (P5).

**Epic** : Document templates PDF • **Priorite** : Must have • **Estimation** : 3h

## User story

En tant que **commercial**, je veux **selectionner un DocumentTemplate pertinent et generer un PDF pre-rempli pour un patient**, afin de **lui envoyer un document personnalise (par mail, WhatsApp, ou impression) en mode demo**.

**Note scope** : pas d'envoi reel. Le commercial telecharge le PDF rempli ou le copie. L'envoi se fait hors-systeme.

## Acceptance Criteria

### API

1. Route render : `GET /api/document-templates/:id/render?processId=<id>` :
   - Charge le template + le process + les donnees liees (patient, interventions, devis)
   - Si `kind=HTML_RENDERED` :
     - Substitue les variables dans `bodyHtml` (reuse `templateRenderer.ts`)
     - Genere le PDF via Puppeteer (reuse `services/pdfGenerator.ts`)
     - Retourne le PDF en streaming
   - Si `kind=PDF_UPLOADED` :
     - Genere une page de garde HTML→PDF avec les variables
     - Concatene la page de garde + le PDF source via `pdf-lib` (a ajouter en dependency)
     - Retourne le PDF concatene
2. Route alternative pour preview en ligne : `GET /api/document-templates/:id/render-preview?processId=<id>` retourne le PDF inline (Content-Disposition inline)
3. Tracking : creer un `DocumentTemplateRenderLog` (table optionnelle, MVP : skip si scope serre, en re-creer si besoin de stats)

### UI Process

4. Onglet "Documents" du ProcessPanel etendu :
   - Section "Templates suggeres" (nouvelle, en haut) :
     - Liste des templates lies aux interventions du process (via `InterventionDocumentTemplate`)
     - Chaque card : nom + kind icon + bouton "Generer PDF" + bouton "Apercu"
   - Le clic "Generer PDF" → telechargement du PDF rendu (browser download dialog)
   - Le clic "Apercu" → modal iframe PDF
5. Sur chaque `DocumentRow` (cf EP10-S03 §5) :
   - Si `documentLabel.documentTemplateId !== null` → bouton "Generer le PDF" inline
   - Variation : le PDF rendu peut etre attache directement a `ProcessDocument.fileUrl` via une action dediee "Generer et attacher"

### UI Action "Generer et attacher"

6. Sur un `ProcessDocument` lie a un label avec template :
   - Action "Generer et attacher" → appelle `/render`, le PDF est uploade dans `ProcessDocument.fileUrl`, status passe a `RECU`
   - Toast "PDF genere et attache au document"

## Tests

- Test integration : `GET /render?processId` avec `kind=HTML_RENDERED` retourne un PDF avec body substitue
- Test integration : `GET /render?processId` avec `kind=PDF_UPLOADED` retourne un PDF avec page de garde + source concatenee
- Test integration : `GET /render` refuse 403 si le commercial n'a pas acces au process (tenant isolation)
- Test integration : `GET /render` 404 si template ou process inexistant
- Test E2E Playwright : commercial ouvre process → onglet Documents → clic "Generer PDF" → fichier telecharge

## Notes techniques

- Dependency a ajouter : `pdf-lib` (~150 KB, MIT) pour concatener PDFs
- Service `services/templateRenderer.ts` etendu :
  - `renderHtmlTemplate(template, context) : Promise<Buffer>` (Puppeteer)
  - `renderPdfTemplate(template, context) : Promise<Buffer>` (page de garde + concat)
- Le PDF source est stocke dans `/uploads/{tenantId}/templates/{uuid}.pdf` — accessible via Multer file system
- Performance : le rendu Puppeteer prend ~1-2s, on accepte ce delai au MVP (loader spinner)
