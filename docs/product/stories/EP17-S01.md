## User story

En tant qu'**editeur de la plateforme**, je veux **une console Back Office separee, protegee par un guard dedie en backend et en frontend**, afin de **gerer la plateforme sans melanger cette surface avec l'app utilisee par les cabinets**.

---

## Contexte

**Etat verifie (audit code 2026-06-01)** :
- Roles existants : `ADMIN`, `COMMERCIAL` (le `CHIRURGIEN` retire — ADR-0002). **Pas de niveau au-dessus d'ADMIN.** Un ADMIN est scope a son tenant.
- Backend : `requireJWT` protege les routes, mais aucun guard "editeur". Pas de router `/api/admin/*`.
- Frontend : `middleware.ts` est NextAuth-only, pas de garde par role pour une zone d'administration.

**Demande utilisateur (2026-06-01)** : *"un middleware dans les routes pour admin, et en front pareil."* Cette story est le socle : le niveau editeur + les deux guards + la coquille du BO. Les fonctions metier du BO sont dans EP17-S02 a S05.

**Reconciliation** : cette story absorbe la partie "niveau editeur" de l'ancienne EP15-S01 (desormais superseded).

---

## Acceptance Criteria

1. Niveau editeur : ajout d'un acteur plateforme (decision a trancher : enum `UserRole.EDITEUR` porte dans le JWT vs table `PlatformAdmin` separee — l'option table isole plus nettement du modele tenant). L'editeur n'appartient pas a un tenant client.
2. Backend : middleware `requireEditor` monte sur tout le router `/api/admin/*` → 403 si l'appelant n'est pas editeur.
3. Frontend : guard sur `/admin/*` (`middleware.ts` + layout BO) → redirect/403 si l'utilisateur n'est pas editeur.
4. Coquille BO : layout dedie + navigation (Tenants, Utilisateurs, Acces support, Logs) — pages branchees sur les stories EP17-S02 a S05.
5. Separation visuelle nette : on identifie au premier coup d'oeil qu'on est dans le BO, pas dans l'app d'un cabinet.
6. Toute action du BO est audit-loggee (EP14-S04) avec l'identite de l'editeur — degradable en log applicatif si S04 pas livre.
7. Le BO est servi sur un chemin dedie (`/admin`). Une isolation plus forte (app/sous-domaine separe) est notee comme evolution possible, hors scope de cette story.

## Tests de securite (obligatoires)

- [ ] Appel `/api/admin/*` par un ADMIN de cabinet → 403
- [ ] Appel `/api/admin/*` par un COMMERCIAL → 403
- [ ] Acces `/admin/*` cote front par un non-editeur → redirect/403, pas de rendu du BO
- [ ] JWT sans flag editeur → routes admin inaccessibles
- [ ] Un editeur n'herite pas implicitement d'un acces aux donnees metier d'un tenant sans passer par les stories dediees (S03/S04)

Fichiers cibles : `apps/backend/tests/security/backoffice-guard.test.ts` + e2e `/admin`

## Notes techniques

- **Decision role** : documenter enum `EDITEUR` vs table `PlatformAdmin` + impact sur `requireJWT`, le JWT et Prisma `$extends` (l'editeur opere cross-tenant, l'isolation des cabinets entre eux ne doit pas regresser).
- **Front guard** : etendre `middleware.ts` sans casser le `withAuth` NextAuth existant.
- **Routing** : prefixe `/api/admin/*` cote backend, `/admin/*` cote front.
