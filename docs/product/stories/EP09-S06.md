# EP09-S06 — UI envoi manuel message + video personnalise (mock no-op)

**Epic** : Follow-up dedie • **Priorite** : Must have • **Estimation** : 3h

## User story

En tant que **commercial**, je veux **envoyer manuellement un message (mail / SMS-WhatsApp / video) personnalise a un patient en follow-up**, afin de **declencher une relance ad-hoc en plus des templates pre-bindes**.

**Note scope** : le bouton "Envoyer" ne declenche aucun envoi reel. Il logue l'action en mode demo (Brief Florian : "on le fait manuellement en mode démo ducoup").

## Acceptance Criteria

### Schema Prisma

1. Nouvelle table `MessageSendLog` :
   - `id : UUID PK`
   - `processId : UUID FK Process` (cascade delete)
   - `messageTemplateId : UUID FK MessageTemplate?` (null si message custom one-shot)
   - `kind : Enum MessageKind` (snapshot du kind au moment de l'envoi)
   - `subject : String?` (snapshot rendu apres substitution variables)
   - `body : Text` (snapshot rendu apres substitution)
   - `mediaUrl : String?` (snapshot)
   - `userId : UUID FK User` (qui a "envoye")
   - `sentAt : DateTime DEFAULT now()`
   - `@@index([processId, sentAt])`

### API

2. Nouvelle route `POST /api/processes/:id/send-message` :
   - Body : `{ messageTemplateId?, kind, subject?, body, mediaUrl?, customizations? }`
   - `customizations` est un patch sur `subject`/`body` (le commercial peut amender un template avant envoi)
   - Backend : 
     - Charge le template si `messageTemplateId` fourni, applique `renderTemplate` avec contexte `{patient, intervention, cabinet, user}`
     - Applique les `customizations` sur le rendu
     - Cree un `MessageSendLog` (snapshot fige)
   - **Pas d'envoi externe** — c'est un log demo
   - Reponse : `{ id, sentAt, body, ... }` (pour confirmation UI)
3. Nouvelle route `GET /api/processes/:id/messages` :
   - Liste `MessageSendLog` du process (orderBy sentAt desc)
   - Inclut `messageTemplate.name` si lie

### UI

4. Onglet "Suivi" du ProcessPanel (cf EP09-S03) etendu :
   - Section "Templates pertinents" en haut :
     - Cards des templates lies via EP09-S05 (filtres par intervention + sub-stage actuel)
     - Chaque card : `kind` icon + name + preview short (3 lignes) + bouton "Personnaliser & envoyer"
   - Section "Envoyer un message libre" (collapsed par defaut)
     - Form vierge : `kind` (MAIL/SMS_WHATSAPP/VIDEO), subject, body, mediaUrl
     - Bouton "Envoyer"
5. Dialog "Personnaliser & envoyer" :
   - Pre-rempli avec le template rendu (post-substitution variables)
   - Editable : subject, body, mediaUrl
   - Toggle "Envoyer en demo" (ne fait que loguer) — explicite a l'user que rien ne part en vrai
   - Apres envoi : toast "Message logue (mode demo)" + refresh historique
6. Section "Historique" en bas :
   - Liste `MessageSendLog` chronologique
   - Chaque entree : `kind` + `subject` ou body excerpt + date + bouton "Voir le contenu integral" (dialog readonly)
   - Badge "DEMO" sur chaque entree (pour eviter toute confusion en demo client)

## Tests

- Test integration : `POST /send-message` avec template + customizations cree un log avec body rendu + custom
- Test integration : `POST /send-message` sans template (custom one-shot) cree un log avec messageTemplateId=null
- Test integration : `GET /messages` retourne les logs du process avec inclusion du template
- Test unit : `renderTemplate` substitue toutes les variables connues, laisse les inconnues telles quelles ({{unknown}} reste {{unknown}})

## Notes techniques

- Le toggle "Envoyer en demo" est purement decoratif au MVP — il n'y a pas de mode "production" (pas d'envoi reel)
- La substitution variable est faite serveur — le client reçoit le rendu fige
- Markdown du `body` (kind=MAIL) rendu cote client via `react-markdown` ou similaire (deja installe ? sinon ajout dependency)
