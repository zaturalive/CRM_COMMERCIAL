## User story

En tant qu'**utilisateur commercial**, je veux **un champ remise dedie sur le devis**, afin de **ne plus bricoler avec des frais negatifs qui font perdre l'information**.

---

## Contexte

**Retour terrain** : demande HAUTE cote commercial (`RETOUR-COMMERCIAL-2026-05-27.md` §2.2 : *"Actuellement elle bricole avec des frais negatifs = perte d'info"*) et confirmee par Cecillia (§Devis : ajouter une remise). Aujourd'hui il n'existe pas de champ remise structure.

**Nuance metier (feedback Cecillia)** : cote chirurgie, la remise s'applique uniquement sur les honoraires praticien. Cote commercial non-HDS, on retient une remise simple sur le total (ou les honoraires/prestations) — a confirmer avec Florian. On ne reintroduit pas la logique medicale.

---

## Acceptance Criteria

1. Migration Prisma : champ `Devis.discount` (montant) + `Devis.discountType` (`AMOUNT` | `PERCENT`) — ou structure equivalente a trancher.
2. UI DevisBuilder : champ remise (montant ou pourcentage) avec recalcul du total en consequence.
3. Calcul : le total tient compte de la remise ; la remise est snapshotee a la creation comme les autres montants (coherence avec EP05-S01).
4. Garde : la remise ne peut pas rendre le total negatif (borne a 0).
5. Le PDF (EP16-S01) affiche la ligne remise quand elle existe.
6. Les KPIs / CA (dashboard) utilisent le total **apres** remise (verifier l'impact sur EP08).

---

## Tests (obligatoires)

- [ ] Remise montant fixe → total = base - remise
- [ ] Remise pourcentage → total = base x (1 - taux)
- [ ] Remise > base → total borne a 0, pas de negatif
- [ ] Remise snapshotee a la creation (pas recalculee si le bareme change apres)
- [ ] PDF affiche la remise ; CA dashboard coherent avec le total apres remise

Fichiers cibles : `apps/backend/tests/unit/devis-discount.test.ts` + e2e DevisBuilder

---

## Notes techniques

- **Calcul** : centraliser le calcul total (avec remise) dans une fonction unique reutilisee par UI + PDF + KPIs, pour eviter les divergences.
- **Type remise** : commencer simple (montant OU pourcentage) ; ne pas sur-concevoir (Mantra #37).
- **Impact** : verifier les ecrans qui lisent le total devis (process panel, dashboard, agenda progression paiement).
