## User story

En tant que **developpeur**, je veux **ajouter un sous-etat au follow-up** pour modeliser les colonnes J+0/J+1/J+3/J+7/J+14/J+30/Abandon, afin que **le sous-pipeline ait une donnee pereenne dans la BDD**.

## Acceptance Criteria

### Schema Prisma

1. Nouvel enum `FollowupSubStage` : `J0`, `J1`, `J3`, `J7`, `J14`, `J30`, `ABANDON`
2. Champ `Process.followupSubStage : FollowupSubStage?` (null tant que `stage != FOLLOWUP`)
3. Champ `Process.followupSubStageEnteredAt : DateTime?` (utilise pour calculer "X jours dans cette etape")
4. Index `@@index([tenantId, stage, followupSubStage])` sur Process
5. Migration Prisma : `add_followup_substage`

### Logique metier (lib/processTransitions.ts ou nouveau lib/followup.ts)

6. Quand `Process.stage` passe a `FOLLOWUP` :
   - Si `followupSubStage` est null → set `J0` + `followupSubStageEnteredAt = now()`
   - Sinon laisser tel quel (ne pas reset si re-passage)
7. Quand `Process.stage` quitte `FOLLOWUP` (vers un stage pipeline ou EFFECTUEE/ANNULEE) :
   - Reset `followupSubStage = null` + `followupSubStageEnteredAt = null`
8. Helper `computeDaysSinceSubStageEntry(followupSubStageEnteredAt) : number | null` exporte depuis `lib/followup.ts`

### API

9. La route `PATCH /api/processes/:id/followup` initialise `followupSubStage = J0` automatiquement
10. La route `PATCH /api/processes/:id/stage` (vers stage pipeline) reset les champs follow-up via le bloc `clearSideExit` deja existant

## Tests

- Test unit `lib/followup.ts` : `computeDaysSinceSubStageEntry` retourne le delta en jours, null si entree null
- Test integration : `PATCH /api/processes/:id/followup` cree un process avec `followupSubStage = J0`
- Test integration : `PATCH /api/processes/:id/stage` vers POST_CONSULT depuis FOLLOWUP reset les champs follow-up
- Test schema : migration applique cleanement sur dataset de seed

## Notes techniques

- Pas de retro-migration (le seed actuel n'a pas de process en FOLLOWUP avec sub-stage). Si certains existent en demo, ils restent `null` jusqu'a la prochaine action.
- Les transitions inter-substages (J0 → J1 → J3...) sont gerees dans EP09-S03 via une route dediee `/sub-stage`, pas ici.
- `J30` et `ABANDON` ne sont pas auto-archivants au MVP — l'archivage reste manuel.
