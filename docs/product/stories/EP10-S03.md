# EP10-S03 — UI association template ↔ intervention + template ↔ DocumentLabel

**Epic** : Document templates PDF • **Priorite** : Must have • **Estimation** : 1h30

## User story

En tant que **administrateur**, je veux **lier un DocumentTemplate a une Intervention et a un DocumentLabel** depuis leurs pages d'edition respectives, afin que **les commerciaux voient les bons templates au bon moment**.

## Acceptance Criteria

### API

1. Routes association intervention :
   - `GET /api/interventions/:id/document-templates` (templates lies, sortes par `order`)
   - `POST /api/interventions/:id/document-templates` body `{ documentTemplateId, order? }`
   - `DELETE /api/interventions/:id/document-templates/:bindingId`
2. Route association DocumentLabel :
   - `PATCH /api/document-labels/:id` accepte deja un body — etendre pour accepter `documentTemplateId : string | null`
   - Pas besoin de table de jointure (relation 1:1 deja presente sur le schema, cf EP10-S01)

### UI Intervention

3. Sur la page edition d'une `Intervention`, sous-section "Documents et templates" :
   - Sous-section A "Documents requis (DocumentLabel)" — existant EP02-S05
   - Sous-section B "Templates de documents a envoyer" — nouveau
     - Tableau : `templateName | kind | actions`
     - Bouton "+ Lier un template" → dialog avec select `DocumentTemplate` (filtre `isActive=true`)
     - Drag pour re-order

### UI DocumentLabel

4. Sur la page edition d'un `DocumentLabel` (formulaire dans la section parametrage labels) :
   - Nouveau champ "Template a generer" : select `DocumentTemplate` + option "Aucun"
   - Si selectionne → la fiche label affiche "Genere via : [template name]"

### UI ProcessDocument

5. Quand un `ProcessDocument` a son `documentLabel.documentTemplateId !== null` :
   - Affichage d'un bouton "Generer le PDF" dans `DocumentRow` (DocumentsTab.tsx)
   - Le bouton declenche le rendu (cf EP10-S04)

## Tests

- Test integration : POST binding intervention ↔ template → GET retourne le template
- Test integration : PATCH document-label avec documentTemplateId → relation persiste
- Test integration : delete template avec bindings → bindings cascade ou setNull cohérent
- Test E2E : parcours admin complet (create template → lier intervention → ouvrir process → voir template suggere)

## Notes techniques

- `InterventionDocumentTemplate` : pattern identique a `InterventionDocumentLabel`
- Pour le DocumentLabel, le champ FK direct simplifie la jointure (pas besoin de table intermediaire pour 1:1)
