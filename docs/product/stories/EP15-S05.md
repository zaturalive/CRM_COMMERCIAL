## User story

En tant qu'**editeur**, je veux **garantir que le mode demo et le switcher de role sont inactifs sur un cabinet de production**, afin qu'**un vrai client ne puisse pas changer de role arbitrairement ni voir des artefacts de demo**.

---

## Contexte

**Etat verifie (audit code 2026-06-01)** :
- Frontend : `RoleSwitcher.tsx:12` lit `const DEMO_MODE = process.env.NEXT_PUBLIC_DEMO_MODE === "true"` et n'affiche les boutons de switch que si vrai. `.env.example` met `NEXT_PUBLIC_DEMO_MODE=true` en dev, `false` dans le template prod.
- Backend : `app.ts:82` monte `/api/demo/switch-role` si `env.NODE_ENV !== "production" || env.DEMO_MODE`.

Donc le mecanisme **peut** etre coupe, mais ce n'est pas verifie/verrouille sur le serveur de prod. Cette story le transforme en garantie testee, pas en hypothese de config. Backlog §9 : "Desactivation de DEMO_MODE en prod reelle".

---

## Acceptance Criteria

1. En configuration de production (`NODE_ENV=production`, `DEMO_MODE` non defini), la route `/api/demo/switch-role` repond 404/403.
2. Le `RoleSwitcher` n'est pas rendu quand `NEXT_PUBLIC_DEMO_MODE !== "true"`.
3. Documentation de deploiement : la checklist de mise en prod inclut "DEMO_MODE off + verifie" (curl sur la route demo + absence du switcher).
4. Garde-fou : un test automatise verifie qu'en mode production simule, la surface de demo est absente (pas seulement masquee cote front).
5. Les donnees/labels de demo ne sont pas seedes sur un tenant de production (verifier le chemin de seed reel vs `load-fake-data`).

---

## Tests de securite (obligatoires)

- [ ] `NODE_ENV=production` sans `DEMO_MODE` → `POST /api/demo/switch-role` = 404/403
- [ ] `NEXT_PUBLIC_DEMO_MODE` non "true" → RoleSwitcher absent du DOM
- [ ] Un COMMERCIAL ne peut pas atteindre une route de demo pour s'octroyer un autre role
- [ ] Tenant de prod → pas de donnees de demo seedees

Fichiers cibles : `apps/backend/tests/security/demo-mode-off.test.ts`

---

## Notes techniques

- **Verrou serveur** : s'appuyer sur `NODE_ENV=production` cote backend (deja la condition de montage) ; le rendre explicite et teste.
- **Frontend** : `NEXT_PUBLIC_*` est inline au build (cf. backlog §8 lessons learned) — donc la valeur prod doit etre figee **au build** de l'image, pas au runtime.
- Coordination legere avec l'infra (l'image de prod doit etre buildee avec `NEXT_PUBLIC_DEMO_MODE=false`).
