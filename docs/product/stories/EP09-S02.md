## User story

En tant que **commercial**, je veux **une page dediee `/follow-up`** avec son propre kanban (J+0, J+1, J+3, J+7, J+14, J+30, Abandon), afin de **suivre les patients en relance independamment du pipeline principal**.

## Acceptance Criteria

### Routing

1. Nouvelle route Next App `/app/(app)/follow-up/page.tsx`
2. Sidebar role-aware : entree "Follow-up" pour COMMERCIAL et ADMIN (visible aussi pour CHIRURGIEN en lecture seule, cf. EP04-S05 pattern)
3. URL hash `?process=<id>` ouvre le ProcessPanel comme dans pipeline (reuse `useProcessPanelStore`)

### API

4. Nouvelle route `GET /api/follow-up` retourne 7 colonnes (J0/J1/J3/J7/J14/J30/ABANDON) :
   - `processes` filtres par `stage = FOLLOWUP` ET `isArchived = false`
   - Groupes par `followupSubStage`
   - Stats par colonne : `count`, `caEnAttente` (somme `estimatedAmount`), `avgDaysInStage`
5. Reuse `enrichProcess` deja exporte (refactor mineur depuis `routes/pipeline.ts` → `lib/processEnrichment.ts`)
6. Pas d'archives, pas d'effectuees, pas de annulees

### Route transition sub-stage

7. Nouvelle route `PATCH /api/processes/:id/follow-up-substage` :
   - Body : `{ subStage: FollowupSubStage }` (J0 | J1 | J3 | J7 | J14 | J30 | ABANDON)
   - Refus 422 si `process.stage !== FOLLOWUP`
   - Met a jour `followupSubStage` + `followupSubStageEnteredAt = now()`
   - Cree un FollowupStepLog (cf EP09-S03) si la story est livree, sinon TODO commentaire

### UI Kanban

8. 7 colonnes horizontales scrollables (mobile : scroll horizontal)
9. Border-left amber 4px sur tout (alignement avec section parallele actuelle)
10. Header colonne : nom + count + somme CA potentiel
11. ProcessCard reuse celles du pipeline (memes badges, meme info)
12. Ajout d'un badge "Xj dans cette etape" sur chaque card (calcule depuis `followupSubStageEnteredAt`)
13. Drag & drop @dnd-kit identique a la pipeline (memes sensors, meme PointerSensor)
14. Optimistic update (cf. EP12-S01 pattern) : la carte se deplace immediatement, refetch background

### Filtres header

15. Search par nom patient (q param)
16. Filtre par `followupReason` (TEMPS / ARGENT / HESITATION / AUTRE / Tous)
17. Compteur "X dossiers en follow-up" (somme totale)

## Tests

- Test integration : drag de J0 a J3 met a jour `followupSubStage` + `followupSubStageEnteredAt`
