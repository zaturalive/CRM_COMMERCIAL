# EP05-S01 — Devis + DevisIntervention + snapshot a la creation

**Epic** : Devis • **Priorite** : Must have • **Estimation** : 3h

## User story

En tant que **chirurgien**, je veux **creer un devis pre-rempli depuis les interventions cochees du process** avec les frais supp associes, afin de **ne pas ressaisir ce que le commercial a deja cochee**.

## Acceptance Criteria

1. Route `POST /api/processes/:id/devis` cree un `Devis` + les `DevisIntervention` en une transaction :
   - Pour chaque `ProcessIntervention` du process, creer une `DevisIntervention` avec snapshot :
     - `priceHonoraires` copie depuis `Intervention`
     - `duration` copie depuis `Intervention`
     - `cliniqueId = NULL` (rempli par commercial plus tard)
   - Pour chaque `InterventionFee` actif de l'intervention, creer une `DevisInterventionFee` avec snapshot (label, price, qty)
2. Reference auto-generee : `DEV-YYYY-XXXX` (sequence par tenant)
3. Statut initial : `BROUILLON`, passe a `TECHNIQUE_REMPLI` quand >= 1 `DevisIntervention`
4. Hook `syncProcessDocuments(processId)` appele (cf. EP06-S01)
5. Transition `CONSULTATION → POST_CONSULT` auto si devis technique rempli
6. GET `/api/devis/:id` retourne le devis avec toutes les relations (devisInterventions, fees, options, custom options, stays, process + client)
7. `GET /api/devis/:id/total` calcule le total en direct (cf. formule data-model.md §4.3)

## Tests

- Test unit : creation devis avec 2 interventions → 2 DevisIntervention + leurs frais snapshotes
- Test unit : modif prix catalogue apres snapshot → prix dans le devis reste le meme
- Test integration : POST route → statut `TECHNIQUE_REMPLI` si au moins une intervention

## Notes techniques

- Tables : `Devis`, `DevisIntervention`, `DevisInterventionFee` (cf. data-model.md §2.11-2.13)
- Sequence reference : `reference = 'DEV-' + year + '-' + str(count + 1).padStart(4, '0')`
- Prix en **centimes** partout
